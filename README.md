# 🌍 GeoAnalytics Dashboard

React-приложение для пространственно-временного анализа данных. Демонстрирует надежную архитектуру синхронизации карты, временной шкалы и аналитических графиков.

## 🏗 Архитектура
Проект построен по принципам модульной архитектуры и **Config-Driven подхода**.
Все состояние приложения (Application State) централизовано в глобальном хранилище **Vedro**, что реализует паттерн Single Source of Truth. 

* **Config-Driven подход**: Вся метаинформация о слоях (цвета, лимиты, ключи значений) вынесена в единый конфигурационный файл (`layerConfig.ts`). Компоненты динамически подтягивают эту конфигурацию, что позволяет добавлять новые слои без изменения JSX и бизнес-логики компонентов.
* **Единый визуальный язык**: Использование единого конфига гарантирует, что визуальное кодирование (например, цвета слоев) будет абсолютно консистентным как на аналитических графиках, так и на карте.
* **Слабая связанность**: **Timeline, Map и Charts** являются "глупыми" потребителями (subscribers) состояния и не общаются друг с другом напрямую.
* Двусторонняя синхронизация реализована через подписку на поле `currentTime`: клик по графику или скролл таймлайна обновляют стейт, что реактивно обновляет все связанные UI-модули.

## 🗺 Выбор картографической библиотеки: Leaflet
Выбор пал на **Leaflet** (через обертку `react-leaflet`), потому что:
1. Это легковесное, стабильное и проверенное временем open-source решение без vendor-lock.
2. Не требует API-ключей или сложной регистрации для базового использования.
3. Имеет огромную экосистему плагинов и отличную поддержку React-сообществом.

## 🪣 Управление состоянием (Vedro) и Производительность
Управление активными слоями и загрузкой данных делегировано Vedro.
Особое внимание уделено следующим аспектам:

* **Race Conditions**: при быстром скролле таймлайна инициируются десятки асинхронных запросов. Чтобы устаревшие данные не перезаписали актуальные (если сервер ответил с задержкой), в слой работы с данными интегрирован `AbortController`. Смена времени автоматически вызывает `abort()` для всех pending-запросов.
* **Оптимизация рендеринга слоев (React-Leaflet)**: Вместо полного пересоздания слоя (Re-mounting) при каждом изменении данных, используется `ref` и нативные методы Leaflet API (`clearLayers()` и `addData()`). Это предотвращает утечки памяти и кардинально снижает нагрузку на браузер при быстром переключении времени.
* **Типобезопасность**: Интегрированы строгие интерфейсы (`FeatureCollection`) вместо `any`, что гарантирует предсказуемость структуры данных на всех этапах (от API до рендеринга).

## 🚀 Стратегия масштабирования (до 100+ слоев)
Текущая реализация использует GeoJSON для легкости прототипирования. При росте до 100+ слоев и сотен тысяч полигонов архитектура предполагает:
1. **Переход на Vector Tiles (MVT)**: Vedro будет хранить не сами геоданные, а параметры для формирования тайловых URL-ов. Рендеринг ляжет полностью на плечи GPU.
2. **Web Workers**: Парсинг и фильтрация временных рядов для аналитики Recharts будет вынесена в отдельные потоки, чтобы не блокировать UI браузера при перерисовке карты.
3. **Lazy Loading**: Динамический импорт конфигураций слоев (code splitting).
